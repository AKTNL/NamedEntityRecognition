## 一、任务背景与文献定位

本项目以 **GPT-NER: Named Entity Recognition via Large Language Models**（Wang et al., 2023，arXiv:2304.10428）为方法参考。本地 [论文原文](GPT-NER_生成式NER.pdf)的作者单位包括北京大学、香浓科技、浙江大学、南洋理工大学和 Amazon；原稿将北京智源列为作者单位的表述已更正。

论文讨论序列标注与自回归生成之间的任务形式差异，使用 `@@实体##` 标记把 NER 转换为文本生成，并研究示例检索和自验证机制。论文的低资源结论来自其自身实验，不能作为本项目已验证的结论。

本项目将方法适配到中文 CLUENER2020，以本地 **Qwen2.5-1.5B-Instruct** 替代论文的 GPT-3，并增加 LoRA 微调分支。语料、语言、基座、检索器和训练方式均有变化，因此不能直接比较本地与原论文的绝对 F1，也不能将差距只归因于模型规模。

## 二、生成式 NER 的任务形式与错误风险

### 2.1 序列标注与文本生成

BERT 等抽取式模型对输入 token 分类，再映射回字符位置。它们不需要生成实体文本，但仍可能发生边界、类别和 token 对齐错误。

自回归模型逐 token 生成输出，需要同时处理实体判断与输出格式。无约束生成可能出现改写原文、标记不配对、遗漏实体或输出错误索引。模型可以输出字符索引，但其正确性仍需验证；不能概括为“大模型无法输出位置”。

同一实体字符串在原文多次出现时，单纯字符串匹配可能找到错误位置。本地历史评测器采用原文查找，因此不能将其描述成任意情况下都无歧义的字符对齐。

### 2.2 过度预测与原文外实体

原论文第 6 页给出 `Rare Hendrix song sells for $17` 的例子：GPT-3 在抽取地点时将 `Hendrix` 标为地点。这是**论文案例**，不是本地 Qwen 实验结果。该例属于类别误判，也不同于本项目统计的“实体字符串在原文中无法定位”。

当前本地实验采用 `@@##` 模板，没有通用列表提示与该模板的受控比较，所以不能据此量化模板本身的收益，也不能仅凭输出推断模型的“意图”或注意力机制的具体变化。

## 三、GPT-NER 的方法与本地实现

### 3.1 标记生成与实体解析

提示模型复制原句，并仅在目标类别实体两端添加 `@@` 和 `##`：

```text
目标类别：公司
输入：雷军在小米科技做发布会。
目标输出：雷军在@@小米科技##做发布会。
```

保留原文上下文有利于后续解析，但这是一种提示约定，不是强制解码约束。模型仍可能漏字、改写或生成不配对标记，不能声称“从根源上杜绝格式错误”。

本地流程如下，其中三种检索策略择一使用；0-shot 提示跳过检索：

```text
原句 + 目标类别
  → 构造提示（可含 random / sentence / entity 检索示例）
  → 模型生成 @@实体## 标记文本
  → 可选自验证（本文所有已保存运行均未启用）
  → 解析、原文定位、跨类型冲突消解
  → BIO 序列与实体级评测
```

### 3.2 三种示例检索策略

实现见 [retriever.py](../generative/retriever.py)：

1. **随机采样（random）**：从训练集的正例池和负例池抽取示例。
2. **句子级检索（sentence）**：按句向量余弦相似度，在两类示例池分别检索。
3. **实体级检索（entity，本地适配）**：用训练实体首字符的上下文表示建索引，将待测句所有字符位置作为候选，按近邻相似度筛选并去重训练句；负例仍用句子级检索。它不使用待测句金标实体，也不是原论文配置的原样复制。

本项目使用中文编码器和本地候选构造。检索对照能反映本地实现之间的差异，不能直接复现或解释原论文中每个模块的贡献。

### 3.3 自验证机制及实验状态

论文提出对初次抽取的实体追加类别判断，例如“在句子 X 中，E 是否属于目标类别？”。其目标是过滤错误候选，但也可能误删正确实体，需要比较启用前后的 precision、recall 和成本。

本地已有 [self_verify.py](../generative/self_verify.py)，但**本文所有已保存运行均为 `self_verify=false`**。因此不能声称本项目已验证自验证的收益，或将当前低格式异常计数归功于自验证。

## 四、CLUENER2020 数据适配与评测口径

### 4.1 按类别构造查询与训练样本

数据转换见 [convert_cluener.py](../generative/convert_cluener.py)，本项目选择“原句 × 目标类别”的 MRC 形式：

- **开发集**：每句展开全部 10 类，不依据金标选择需要查询的类别，避免使用类型先验信息。全量 dev 共 **1,343 句、13,430 条查询、3,072 个金标实体**。
- **训练转换**：默认只展开句中出现的类别。LoRA 训练另外为每句加入最多 3 个缺失类别作为负例，再从样本池抽取 6,000 条查询；这不等于 6,000 个独立原句。
- **正例目标**：在目标类别实体两侧添加标记。
- **负例目标**：输出不加标记的原句。

负例提供“不应标记实体”的监督，但没有固定其它因素的正负比例消融，不能量化负例注入单独带来的收益。本文所有评测均使用有标签的 **dev**；公开 test 没有标签，不称这些结果为隐藏测试集成绩。

### 4.2 实体 F1 的后处理边界

[历史评测器](../generative/evaluate.py)先提取成对标记中的字符串，再到原文定位；无法定位的字符串被单独计数并丢弃。跨类型重叠候选优先保留较长 span，同长度时按起点和固定类别顺序处理，最后转为 BIO 调用 `seqeval`。

因此，报告中的 F1 衡量的是**经过解析与冲突消解的最终实体输出**，不是直接对原始生成文本打分。原文外实体没有作为普通 FP 直接进入这个 F1，必须同时报告其计数。重复字符串的当前查找调用也可能总命中首处，这属于历史评测的局限。

抽取式和生成式都使用实体级 P/R/F1，但预处理、后处理、训练量和部分实验的样本范围不同。只有标明这些差异，才适合并列展示；不能把“使用同一个指标函数”写成“实验条件完全公平”。

### 4.3 两项生成错误统计的实际定义

| 字段 | 当前实现的含义 | 解读限制 |
| :--- | :--- | :--- |
| `malformed_rate` | 标记计数不匹配或与解析出的实体数不一致的查询数 / 查询总数 | 只是标记异常检测，不覆盖所有改写、截断、重复或语义错误 |
| `hallucination_rate` | 无法在原文定位的实体字符串出现次数 / 查询总数 | 本文称“幻觉计数比”；分子不是去重后的查询数，也不是全部幻觉的发生概率 |
| `n_pred_entities` | 跨类型冲突消解前可定位候选的总数 | 不能直接用作最终 precision 的预测分母 |

指标 JSON 中 P/R/F1 已经是 0–100 的百分数；上述两个 rate 字段是 0–1 的比值，展示时乘 100。例如 `0.0015` 对应 **0.15%**，不是 0.0015%。

## 五、LoRA 有监督微调设计

LoRA 是本项目增加的有监督分支。本文的 **0-shot 只表示提示中不放示例**；模型已经用任务标注微调，不能将结果称为“未经任务训练的零样本能力”。

### 5.1 参数冻结与低秩更新

对选定层的预训练权重 $W_0 \in \mathbb{R}^{d \times k}$ 保持冻结，训练低秩增量：

$$W = W_0 + \Delta W, \qquad \Delta W = \frac{\alpha}{r}BA$$

其中 $A \in \mathbb{R}^{r \times k}$、$B \in \mathbb{R}^{d \times r}$。具体初始化取决于 PEFT 配置与版本；常见默认初始化将 B 置零，使初始低秩增量为零。“冻结基座”不表示训练期间始终 $\Delta W=0$。

### 5.2 提示部分的损失屏蔽

[train_lora.py](../generative/train_lora.py)中的实现为：

```python
input_ids = p_ids + t_ids
labels = [-100] * len(p_ids) + t_ids[:]
```

这使直接语言建模损失仅作用于目标文本和 EOS，是本实现的策略，不是所有 SFT 任务的唯一选择。提示仍参与上下文计算；目标还包含复制原句的普通 token，所以低训练损失不能直接等同于实体识别质量高。

### 5.3 显存控制

本次训练启用梯度检查点，CUDA 路径以 `bfloat16` 加载模型，使用 `batch_size=4` 与 `grad_accum=4`。每次参数更新累计 16 条查询样本，但不能保证与一次性大批次计算逐位相同。这些策略用于降低内存需求，不保证任意长度、批次和运行环境都不会 OOM。

## 七、实验结果与可比性边界

### 7.1 相同 120 句上的检索策略对照

三组运行均取 **dev 前 120 句、1,200 条查询、274 个金标实体**，使用未挂载 LoRA 的 Qwen2.5-1.5B-Instruct。保存的公共配置为 `k=8, seed=42, batch_size=64, max_new_tokens=72, lang=zh_mrc, chat_template=false, self_verify=false`；日志均记录负例比例 0.5。

| 检索策略 | Precision | Recall | Micro F1 | 标记异常率 | 幻觉计数比 |
| :--- | :---: | :---: | :---: | :---: | :---: |
| random | 7.63% | 7.30% | **7.46%** | 45.17% | 7.17% |
| sentence | 28.52% | 26.64% | **27.55%** | 29.00% | 4.25% |
| entity | 32.53% | 34.67% | **33.57%** | 30.58% | 7.00% |

来源：[random 结果](../results/generative/gptner_random_k8_n120.json)、[sentence 结果](../results/generative/gptner_sentence_k8_n120.json)、[entity 结果](../results/generative/gptner_entity_k8_n120.json)；模型挂载和负例比例见对应的 [random 日志](../logs/ab_random_n120.log)、[sentence 日志](../logs/ab_sentence_n120.log)、[entity 日志](../logs/ab_entity_n120.log)。

在这次固定子集运行中，sentence 的 F1 比 random 高 **20.09 个百分点**，entity 比 sentence 高 **6.02 个百分点**。这支持“本地检索策略会影响该子集结果”的观察，但没有多次抽样或重复实验，不能据此推断全量 dev、其它领域或其它模型上的稳定收益。

entity 的 F1 最高，但标记异常率和幻觉计数比都高于 sentence，说明实体质量与格式指标并非同步改善。72-token 输出预算也可能限制长输出；未做长度预算消融，不能量化其影响。

### 7.2 LoRA 在全量 dev 上的结果

该运行使用有监督微调后的适配器，提示 `k=0`，`batch_size=32, max_new_tokens=96, seed=42`，关闭 chat template 与自验证。

| 评测范围 | Precision | Recall | Micro F1 | 标记异常率 | 幻觉计数比 |
| :--- | :---: | :---: | :---: | :---: | :---: |
| 全量 dev：1,343 句 / 13,430 查询 | 43.12% | 40.17% | **41.59%** | **0.15%** | **0.20%** |

来源：[全量结果](../results/generative/gptner_sentence_k0_lora.json)与明确记载适配器挂载的[运行日志](../logs/lora_eval_full.log)。共有 **20 条标记异常查询、27 次无法定位的实体字符串**；百分比采用 JSON 中保存的四舍五入值。

这说明该检查点在当前 dev 上可以较稳定地输出可解析标记，但实体 F1 仍有限。它与 §7.1 同时改变了监督训练、提示长度、输出预算和评测范围，不能将二者差值解释为 LoRA 单独带来的提升，也不能以较低的标记异常率宣称格式问题已经消失。

## 八、错误案例与证据边界

### 8.1 标记不配对

早期材料保留了以下原始输出片段：

```text
台湾的发卡模式，先通过@@跑马圈地
圈的地里面@@选择@@客户
```

这些片段展示了开放标记未闭合或重复开放标记的现象。但片段没有完整的样本 ID、目标类别与原文配对，不适合直接判定实体语义是否错误，也不能据此确认“随机示例导致注意力发散”。检索策略、提示、生成长度等都可能影响输出，需要受控实验验证原因。

### 8.2 “阿森纳”与原文定位失败

100 句 LoRA 结果的 `hallucination_samples` 包含“阿森纳”，且 `n_hallucination=1`。这能支持的结论是：**评测器记录了一次无法在对应原文定位的实体字符串**。

现有汇总没有保留该项对应的 sample_id、完整输入与生成输出，因此不能确认它是否源于球队别名的归一化，也不能据此推断模型调用了某类世界知识。全量运行另记录 27 次无法定位实体，不能沿用小子集的“仅 1 次”描述全量结果。

### 8.3 案例记录的改进方向

后续应保存句子 ID、原文、目标类别、完整 prompt、原始输出、解析实体、冲突消解结果与模型身份，再区分边界错误、类别错误、漏检、原文外实体和格式问题。当前案例支持的是已观察到的输出症状，不是模型内部机制的确定归因。

## 九、双范式结果与结论

### 9.1 全量 dev 的描述性对照

以下三组均使用全量 dev 的 **1,343 句、3,072 个金标实体**，主要指标为实体级 Micro F1。

| 方案 | 下游监督与训练配置 | 评测形式 | Micro F1 |
| :--- | :--- | :--- | :---: |
| BERT | 10,748 个原句，全参数微调 4 epoch，batch=32 | token 分类后实体评测 | **76.05%** |
| MacBERT | 10,748 个原句，全参数微调 4 epoch，batch=32 | token 分类后实体评测 | **76.61%** |
| Qwen2.5 + LoRA | 6,000 条按类型查询，微调 1 epoch，batch=4、累积=4 | 每句 10 类查询，k=0，解析与冲突消解后评测 | **41.59%** |

来源：[BERT](../saved_models/bert/eval_results.json)、[MacBERT](../saved_models/macbert/eval_results.json)、[LoRA 全量结果](../results/generative/gptner_sentence_k0_lora.json)和[LoRA 训练参数](../saved_models/gptner_lora/train_args.json)。未微调 few-shot 的 120 句实验单列在 §7.1，不作为全量 dev 排名中的同范围结果。

在当前配置下，抽取式检查点的实体 F1 高于本地 LoRA 生成式检查点。但训练数据单位与规模、轮次、模型结构和后处理均不同，这不能证明抽取式在所有场景优于生成式，也不能量化某一种架构的独立贡献。这里没有统一的延迟基准或跨领域测试，删除原稿的“毫秒级优势”“泛化极强/极差”等未经验证的排名。

### 9.2 当前证据能够支持的结论

1. **抽取式基线已完成下游复现**：BERT 与 MacBERT 在本地 dev 上分别得到 76.05% 和 76.61% 的 Micro F1。MacBERT 数值上高 0.56 个百分点，但没有多种子统计证据证明差异稳定或显著。
2. **检索策略值得继续研究**：同一 120 句、k=8 的本地对照中，entity、sentence、random 的 F1 依次为 33.57%、27.55%、7.46%。这是单个固定前缀子集上的观察，不能外推为完整复现论文结论或普遍排序。
3. **LoRA 分支已跑通训练与全量评测**：微调约 0.2815% 的参数后，该检查点在无提示示例的全量 dev 评测中得到 41.59% F1，标记异常率为 0.15%。由于缺少来源明确且其它设置一致的未挂载适配器对照，不能断言这些改善全部由 LoRA 引起，也不能称 LoRA 是“最高效”或“唯一可落地”的方案。
4. **结论受实验设计限制**：自验证收益、低资源优势、跨领域能力、检索排序的统计稳定性和统一硬件效率比较均尚未验证。抽取式还使用 dev 选模并报告成绩，存在选模偏差；公开 test 没有标签，本项目没有独立测试集结论。

这些结果为课程项目提供了可检查的实现与实验记录。后续若要扩大结论范围，应优先补齐完整运行元数据、同条件对照和逐样本错误记录，再决定是否增加更多模型或训练轮数。
