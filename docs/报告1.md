## 一、 任务背景与核心文献定位（CLUENER2020）

本项目第一阶段聚焦于命名实体识别（Named Entity Recognition, NER）领域的**经典抽取式（Extractive）范式**。该范式的理论依据与实验基准严格对齐以下权威学术文献：

- **文献全称**：《CLUENER2020: Fine-Grained Named Entity Recognition Dataset and Benchmark for Chinese》
- **发表团队**：CLUE 评测基准委员会（国内最权威的中文 NLP 榜单组织，2020）
- **核心定位与贡献**：
  1. 填补了中文 NLP 领域长期缺乏高质量、大规模、细粒度实体标注集的空白（传统数据集如 MSRA 仅有 PER/LOC/ORG 3~4 类）；
  2. 提出了涵盖现实互联网高频场景的 **10 大细粒度实体分类标准**；
  3. 奠定了以预训练语言模型（BERT/RoBERTa）为底座、结合字符级 BIO/BIOS 序列标注的经典微调技术基线。

## 三、 序列标注机制与数据管道核心原理

### 3.1 标注体系演进：BIOS（原论文）vs BIO（工程实践）

* **BIO 体系（21 维）**：
  - `O`：非实体字符（Outside，1维）；
  - `B-XXX`：实体起始字符（Begin，10维）；
  - `I-XXX`：实体内部及结尾字符（Inside，10维）；
  - 总维度：$1 + 10 \times 2 = 21$ 类。
* **BIOS 体系（31 维，原论文采用）**：
  - 增加 `S-XXX`（Single）：显式标记**单字独立实体**（如姓氏“李”、简称“京”）；
  - 总维度：$1 + 10 \times 3 = 31$ 类。
* **差异权衡分析**：
  原论文使用 BIOS 旨在帮助早期 BiLSTM/CRF 模型消除单字实体何时结束的不确定性；而在现代 Transformer 体系中，Self-Attention 拥有全局上下文视野，BIO 已完全具备强大的边界判别力，且能有效缓解 10 个 `S-` 标签带来的严重样本稀疏性，无缝适配标准化 `seqeval` 评测协议。

### 3.2 标注切片索引陷阱：闭区间 `[start, end]`
CLUENER 的 JSON 标注格式采用闭区间：`"张伟": [[0, 1]]` 表示第 0 位是“张”，第 1 位是“伟”。
在 Python 字符切片中必须写作 `text[start : end + 1]`，否则词尾必被切断。

### 3.3 特殊标记与 PyTorch `-100` 梯度屏蔽机制

当单字序列送入分词器时，会自动附加特殊标记：
```
Token:          [CLS]   张     伟     在    [SEP]   [PAD]   [PAD]
input_ids:        101   2453   7428   1762    102      0       0
attention_mask:    1      1      1      1      1       0       0
labels:          -100     1      2      0    -100    -100    -100
```
- **核心逻辑**：
  `[CLS]`（首标记）、`[SEP]`（尾标记）、`[PAD]`（填充标记）**绝不可标记为 `O`**（否则模型会走捷径盲猜 `O`）。
- **底牌机制**：
  利用 PyTorch 交叉熵损失函数内置的 `ignore_index = -100`。凡是标签值为 `-100` 的位置，PyTorch 在反向传播求导时**严格跳过、损失算作 0**，确保仅真实汉字参与参数更新。
- **对齐实现**：
  利用 HuggingFace `BertTokenizerFast` 的 `encoding.word_ids()` 方法，当 `word_idx is None` 时精确赋为 `-100`。

## 四、 模型架构、超参数物理含义与显存核算

### 4.1 线性分类头网络结构（Token Classification Head）
```
输入 Token IDs ──► [ BERT / MacBERT 底座 (12层 Transformer) ] ──► 输出 768 维字符表征
                                                                      │
                                                           [ Dropout (p=0.1) ]
                                                                      │
                                                    [ Linear (768 ──► 21 维输出) ]
                                                                      │
                                                           每个字的 21 类 Logits
```
- 模型前向传播直接由 HuggingFace 内部计算 `CrossEntropyLoss(ignore_index=-100)`，无需额外手动 Softmax。

### 4.2 论文推荐超参数物理含义拆解

| 超参数 | 设定值 | 通俗比喻 | 深度物理含义与设置依据 |
| :--- | :--- | :--- | :--- |
| **`Epochs`** | **4** | 练习册完整刷 4 遍 | 预训练模型迁移学习的收敛甜点区；过少（<2）欠拟合，过多（>5）在特定样本上过拟合。 |
| **`Batch size`** | **32** | 每做完 32 题核对一次答案 | 兼顾梯度估计稳定性与矩阵并行利用率，显存占用平稳。 |
| **`Learning rate`**| **3e-5** | 改错时的微调步长 | 预训练模型参数已高度结构化，学习率必须极小（雕花式微调），防止破坏底层通用语义表征。 |
| **`Length`** | **128** | 答题纸限定长度 | 覆盖 CLUENER 最长 50 字样本，确保 100% 零截断。 |
| **`Warmup`** | **10%** | 剧烈运动前的热身 | 前 10% 步数学习率从 0 线性升至 3e-5，保护随机初始化的分类头不冲毁底座特征。 |

### 4.3 RTX 5060 显卡硬件资源开销核算（8GB 显存）
- BERT-base 权重与梯度：约 $0.85\text{ GB}$
- AdamW 一阶/二阶动量状态：约 $0.85\text{ GB}$
- 前向激活值（$B=32, L=128$）：约 $2.0\text{ GB}$
- **总显存峰值开销**：约 **$3.7\text{ GB}$**（在 8GB 显存中占用不到一半，安全边际极高，4 轮训练仅耗时约 2 分钟）。

## 五、 训练引擎（train.py）代码架构深度剖析

整套训练脚本遵循现代学术研究级可复现流程，分为五大模块：

1. **可复现性基石 (`set_seed`)**：
   显式锁定 Python `random`、`numpy`、`torch.manual_seed` 以及 `torch.cuda.manual_seed_all`，确保随机种子为 42 时结果绝对确定。
2. **数据流装配 (`CluenerDataset` + `DataLoader`)**：
   多进程批次打包，训练集开启 `shuffle=True` 打乱题目顺序，验证集 `shuffle=False` 保证测试基准严正。
3. **优化器与动态学习率调度**：
   使用带权重衰减的 `AdamW`，配合 `get_linear_schedule_with_warmup` 实施线性升温与衰减。
4. **训练主步进（Step Loop）**：
   标准五步：`outputs = model(...)` $\rightarrow$ `loss.backward()` $\rightarrow$ `clip_grad_norm_`（梯度裁剪防爆炸） $\rightarrow$ `optimizer.step()` $\rightarrow$ `scheduler.step()` $\rightarrow$ `zero_grad()`。
5. **严苛评估与权重自动存档 (`evaluate`)**：
   使用 `torch.argmax` 预测类别，**严格剔除 `-100` 特殊标记**后还原为真实字符标签列表，送入 `seqeval` 计算实体级 Micro-F1。若验证集打破历史纪录，自动执行 `save_pretrained` 保存最佳模型权重与评测 JSON。

## 七、 进阶消融实验：哈工大 MacBERT 对比分析

为进一步探索模型底层预训练机制对下游任务的影响，我们引入哈工大讯飞联合实验室的 **`hfl/chinese-macbert-base`** 进行了同条件（控制变量）消融实验：

### 7.1 双模型同台 PK 最终成绩单

| 实验组别 | 预训练模型底座 | 轮次 | 批次 | 学习率 | 最优实体验证 F1 | 相对提升 ($\Delta$) | 最佳 Epoch |
| :---: | :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **基准组 (Baseline)** | `bert-base-chinese` | 4 | 32 | 3e-5 | **76.05%** | — | Epoch 4 |
| **改进组 (Proposed)** | `hfl/chinese-macbert-base` | 4 | 32 | 3e-5 | **76.61%** | 🚀 **+0.56%** | Epoch 4 |

### 7.2 性能跃迁的 NLP 底层原理解析

1. **MLM as Correction（纠错式掩码）消除预训练鸿沟**：
   原生 BERT 预训练时强制填充 `[MASK]`，但下游微调句子中不存在 `[MASK]`，导致预训练与微调上下文表征存在分布偏移（Discrepancy）。MacBERT 采用“相似词/同义词替换”来进行掩码，使得预训练输入与下游真实文本形态完全统一。
2. **Whole Word Masking（全词掩码，WWM）强化复合长实体边界感知**：
   中文 NER 最难的攻坚点在于长实体的边界界定（如复合公司名、政府机构名）。原生 BERT 容易按单字破碎掩码，而 MacBERT 引入词级别打包掩码，强迫 Transformer 编码器建立起对整词词组边界的敏感度，显著改善了实体边界切分能力。

### 7.3 工程实战细节记录（排除假性故障）
- 在加载 MacBERT 时，控制台出现 `Thread-auto_conversion` 引起的 `403 Forbidden`。经查证，此为新版 `transformers` 试图联网检查 HuggingFace 论坛讨论区是否有人提交 `.safetensors` PR 的非关键后台子线程，哈工大关闭了讨论区导致报错，完全不影响主线程从本地缓存平稳加载 PyTorch 权重。
- 分类头报告中 `classifier.*` 为 `MISSING`，`cls.predictions.*` 为 `UNEXPECTED`，完全符合预训练头（MLM）卸载、下游微调分类头从头初始化的标准预期。

## 八、 核心评测指标与科学性原理解析（F1 与可复现性）

### 8.1 为什么信息抽取严禁使用准确率（Accuracy）？
CLUENER 数据集中超过 90% 的字符均为非实体 `O`。若构建一个对所有字符恒定预测 `O` 的退化模型，其 Accuracy 仍可高达 95% 以上，但实际实体检出率为 0。

### 8.2 F1-Score：精确率与召回率的调和卫士
- **精确率（Precision / 查准率）**：$\frac{TP}{TP + FP}$，模型挑选出来的实体中挑对的比例（严惩误报）。
- **召回率（Recall / 查全率）**：$\frac{TP}{TP + FN}$，真实世界的所有实体中被成功捕获的比例（严惩漏报）。
- **F1 分数（调和平均数）**：
  $$F_1 = 2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}$$
  调和平均数对微小值有极强的惩罚效应，唯有在模型查得准且捞得全的均衡状态下才能获得高分。

### 8.3 确定性实验与随机种子（Random Seed）
实验中每次运行跑出的 F1 稳定为 `76.05%` 与 `76.61%`，是由于 `set_seed(42)` 锁定了随机初始化权重、DataLoader 洗牌排列与 Dropout 掩码。在学术界，这种确定性是实验**具备可复现性（Reproducibility）**的硬指标；通过调节 `--seed` 可以观察不同初始状态下的指标方差。
