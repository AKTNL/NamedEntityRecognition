## 一、 任务背景与核心文献定位（CLUENER2020）

本项目第一阶段聚焦于命名实体识别（Named Entity Recognition, NER）的**抽取式（Extractive）范式**，以以下文献的数据集和基线设置为参考：

- **文献全称**：《CLUENER2020: Fine-Grained Named Entity Recognition Dataset and Benchmark for Chinese》
- **文献来源**：Xu et al., 2020；原文见 [CLUENER2020.pdf](CLUENER2020.pdf)。
- **核心定位与贡献**：
  1. 填补了中文 NLP 领域长期缺乏高质量、大规模、细粒度实体标注集的空白（传统数据集如 MSRA 仅有 PER/LOC/ORG 3~4 类）；
  2. 提出了涵盖现实互联网高频场景的 **10 大细粒度实体分类标准**；
  3. 奠定了以预训练语言模型（BERT/RoBERTa）为底座、结合字符级 BIO/BIOS 序列标注的经典微调技术基线。

## 三、 序列标注机制与数据管道核心原理

### 3.1 标注体系演进：BIOS（原论文）vs BIO（工程实践）

* **BIO 体系（21 维）**：
  - `O`：非实体字符（Outside，1维）；
  - `B-XXX`：实体起始字符（Begin，10维）；
  - `I-XXX`：实体内部及结尾字符（Inside，10维）；
  - 总维度：$1 + 10 \times 2 = 21$ 类。
* **BIOS 体系（31 维，原论文采用）**：
  - 增加 `S-XXX`（Single）：显式标记**单字独立实体**（如姓氏“李”、简称“京”）；
  - 总维度：$1 + 10 \times 3 = 31$ 类。
* **差异权衡分析**：
  BIOS 显式区分单字实体；BIO 用单独的 `B-XXX` 也可以表示单字实体。本项目选择 BIO 以简化标签集合并使用 `seqeval` 评测，但未进行 BIO/BIOS 对照，不能据此断言 BIO 更准确、BIOS 存在严重稀疏问题或标签体系对分数的具体影响。

### 3.2 标注切片索引陷阱：闭区间 `[start, end]`
CLUENER 的 JSON 标注格式采用闭区间：`"张伟": [[0, 1]]` 表示第 0 位是“张”，第 1 位是“伟”。
在 Python 字符切片中必须写作 `text[start : end + 1]`，否则词尾必被切断。

### 3.3 特殊标记与 PyTorch `-100` 梯度屏蔽机制

当单字序列送入分词器时，会自动附加特殊标记：
```
Token:          [CLS]   张     伟     在    [SEP]   [PAD]   [PAD]
input_ids:        101   2453   7428   1762    102      0       0
attention_mask:    1      1      1      1      1       0       0
labels:          -100     1      2      0    -100    -100    -100
```
- **核心逻辑**：
  本实现将 `[CLS]`、`[SEP]`、`[PAD]` 排除在分类损失与实体评测之外，避免把特殊位置当成真实字符监督。
- **底牌机制**：
  利用交叉熵的 `ignore_index = -100` 忽略这些位置的直接分类损失；这不表示特殊 token 在注意力计算中完全没有梯度影响。上表的 token ID 仅作结构示意，真实 ID 应以 tokenizer 输出为准。
- **对齐实现**：
  利用 HuggingFace `BertTokenizerFast` 的 `encoding.word_ids()` 方法，当 `word_idx is None` 时精确赋为 `-100`。

## 四、 模型架构、超参数物理含义与显存核算

### 4.1 线性分类头网络结构（Token Classification Head）
```
输入 Token IDs ──► [ BERT / MacBERT 底座 (12层 Transformer) ] ──► 输出 768 维字符表征
                                                                      │
                                                           [ Dropout (p=0.1) ]
                                                                      │
                                                    [ Linear (768 ──► 21 维输出) ]
                                                                      │
                                                           每个字的 21 类 Logits
```
- 模型前向传播直接由 HuggingFace 内部计算 `CrossEntropyLoss(ignore_index=-100)`，无需额外手动 Softmax。

### 4.2 本次实验超参数与依据

| 超参数 | 设定值 | 通俗比喻 | 深度物理含义与设置依据 |
| :--- | :--- | :--- | :--- |
| **`Epochs`** | **4** | 练习册完整刷 4 遍 | 采用 CLUENER2020 论文 Table 4 的 BERT 训练轮数；未验证其它轮数的最优性。 |
| **`Batch size`** | **32** | 每做完 32 题核对一次答案 | 兼顾梯度估计稳定性与矩阵并行利用率，显存占用平稳。 |
| **`Learning rate`**| **3e-5** | 改错时的微调步长 | 与论文 Table 4 的 BERT 设置一致；未做学习率搜索。 |
| **`Length`** | **128** | 答题纸限定长度 | 当前数据与 tokenizer 下无长度截断，见 §2.2。 |
| **`Warmup`** | **10%（脚本默认）** | 学习率逐步升高 | 当前 `train.py` 默认前 10% 步数线性升温；评测 JSON 未保存该项，不能单凭默认值确认历史运行实参。 |

### 4.3 硬件资源开销的记录边界
显存占用取决于权重与优化器精度、批次、序列长度、激活缓存和运行环境。当前两份评测 JSON 没有训练总耗时或显存峰值字段，因此不将早期材料中的“3.7 GB”“4 轮约 2 分钟”作为已核实实测值。若正式报告需要效率对比，应在统一硬件和计时边界下补充日志，同时区分加载时间、训练时间与推理时间。

## 五、 训练引擎（train.py）代码架构深度剖析

整套训练脚本遵循现代学术研究级可复现流程，分为五大模块：

1. **可复现性基石 (`set_seed`)**：
   设置 Python、NumPy、PyTorch 和 CUDA 的随机种子，以减少随机性。固定种子不能保证跨硬件、库版本或非确定性 GPU 算子得到完全相同结果。
2. **数据流装配 (`CluenerDataset` + `DataLoader`)**：
   通过 DataLoader 组装批次，训练集开启 `shuffle=True`，验证集使用固定顺序；不将未配置的多进程加载描述为已实现特性。
3. **优化器与动态学习率调度**：
   使用带权重衰减的 `AdamW`，配合 `get_linear_schedule_with_warmup` 实施线性升温与衰减。
4. **训练主步进（Step Loop）**：
   主循环：`outputs = model(...)` $\rightarrow$ `loss.backward()` $\rightarrow$ `clip_grad_norm_` $\rightarrow$ `optimizer.step()` $\rightarrow$ `scheduler.step()` $\rightarrow$ `zero_grad()`。
5. **严苛评估与权重自动存档 (`evaluate`)**：
   使用 `torch.argmax` 预测类别，**严格剔除 `-100` 特殊标记**后还原为真实字符标签列表，送入 `seqeval` 计算实体级 Micro-F1。若验证集打破历史纪录，自动执行 `save_pretrained` 保存最佳模型权重与评测 JSON。

### 7.2 观察结果与机制解释的边界

当前保存的运行中，MacBERT 的 Micro F1 **数值上高 0.56 个百分点**。没有多种子重复实验、方差或显著性检验，不能判断这一差异是否稳定，也不能写成“已证明显著提升”或“已证明没有显著差异”。

MacBERT 的纠错式 MLM 和全词掩码为讨论预训练方法提供了理论背景：前者旨在缓解 `[MASK]` 带来的预训练与微调不一致，后者以词为单位选择掩码位置。但本实验没有逐项移除这些机制，也没有按实体长度统计边界错误，因此不能把 0.56 个百分点归因于其中某一机制，或声称已验证长实体边界的改善。

## 八、 核心评测指标与科学性原理解析（F1 与可复现性）

### 8.1 为什么字符准确率不能替代实体 F1？
按本地字符位置和实体 span 的并集重新统计，训练集非实体字符约占 **73.31%**，开发集约占 **73.11%**。全预测为 `O` 时，字符准确率仍可达到相应比例，但实体召回率与 F1 为 0。因此字符准确率可作辅助统计，不能作为 NER 的主要质量结论；原稿“超过 90%”“95% 以上”没有数据支持。

### 8.2 F1-Score：精确率与召回率的调和卫士
- **精确率（Precision / 查准率）**：$\frac{TP}{TP + FP}$，模型挑选出来的实体中挑对的比例（严惩误报）。
- **召回率（Recall / 查全率）**：$\frac{TP}{TP + FN}$，真实世界的所有实体中被成功捕获的比例（严惩漏报）。
- **F1 分数（调和平均数）**：
  $$F_1 = 2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}$$
  调和平均数对微小值有极强的惩罚效应，唯有在模型查得准且捞得全的均衡状态下才能获得高分。

### 8.3 随机种子、选模偏差与复现记录
`train.py` 提供 `--seed`，默认值为 42，但当前两份 `eval_results.json` 没有保存 seed，不能仅凭代码默认值完整还原历史运行。这里报告的是各自一份已保存检查点的结果，不是多次重复运行均得到同一分数的证据。

此外，dev 集既用于逐轮选择最佳检查点，也用于报告最终成绩，结果可能带有选模造成的乐观偏差。公开 test 没有标签，本项目不能提供独立测试集分数。后续可保存完整命令、环境版本和 seed，并通过多种子实验报告均值、标准差与区间；当前结论不以这些尚未完成的验证为前提。

## 九、 抽取式阶段总结与模型资产落地

本阶段已完成公开权重的下游微调、开发集评测和模型资产保存：
